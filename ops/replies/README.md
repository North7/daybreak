# X 互動回覆

目的：在別人的比特幣討論裡，補上 Daybreak 才有的數字，讓看到的人記住這個帳號、回頭追蹤。不是去貼連結。

挑文章只看一件事：**這篇在講的東西，Daybreak 今天有沒有一個具體數字能印證、補充或反駁它。**有的才回，再依時效和曝光排優先順序。

## 每日流程

1. **找文（Grok）**：日報出來後，把 [`grok-prompt.md`](grok-prompt.md) 裡的整段貼給 Grok。它會讀當天的 `data/notes.json`，回傳一張最多 8 則的候選表（英文 5、中文 3，每則有分數和建議角度）。
2. **寫回覆（Claude）**：在 `daybreak-ops` 資料夾開 session，把 Grok 的表格整個貼上，說「幫我寫回覆」。
3. **發文（你）**：挑要回的，複製貼上。

## Claude 寫回覆時

**先讀當天的數據**：`data/notes.json`（英文 `data/notes.en.json`）的 headline、findings、news、modules，數字細節查 `data/latest.json`、`data/etf.json` 等。只引用數據裡有的數字，不改數字、不自己推算新數字。如果 `notes.json` 的日期不是今天，先跟使用者確認。

**回覆規則**

- **一則只講一個重點數字**，附上日期和來源（例如「ETF 11/02 −3.99 億，兩日 −10.4 億（The Block）」）。來源寫數據的原始出處，不是寫 Daybreak。
- **只講資訊**：不提出場框架（觸發條數、價格階梯、MVRV 賣出線、200 日均線避險），不給買賣建議，不寫「今天不動」這類動作結論。和短影片同一個原則。
- **預設不放連結**。對方問數據來源，或真的需要看圖時，才附 `https://north7.github.io/daybreak/`。
- **語言跟著原文**：中文貼文用繁體中文回，英文貼文回英文。
- **語氣是補充，不是糾正**：要反駁時，先承認對方說對的部分，再用數字說明另一面。
- **長度**：X 加權字數 280 以內（中文字算 2、網址算 23），最好在 200 左右，手機上一眼看完。
- 不寫 emoji 串、hashtag、「DYOR」「NFA」這類套話。

**依建議角度寫**

| 角度 | 怎麼寫 |
|---|---|
| 補數據 | 對方說了 A，補一個他沒提到、但指向同一件事的數字 |
| 交叉驗證 | 用另一個來源或指標確認（或削弱）對方的數字 |
| 提出反例 | 「X 是對的，不過 Y 顯示……」：一個數字、一個解讀 |
| 回答提問 | 直接回答，第一句就給數字 |

**交回的格式**：每則一段

```
#1 <連結>（帳號 · 角度）
回覆：<可直接貼的回覆>
用到的數字：<數字 · 日期 · 來源>
字數：<加權字數>/280
```

算字數用網站同一套算法：

```bash
python3 -c "import sys; sys.path.insert(0, 'pipeline'); from x_len import weight; print(weight(sys.stdin.read().strip()))" <<< '回覆內容'
```

如果某則候選其實和今天的數據對不上，或回了容易變成喊單、吵架，直接說「建議跳過」並寫原因，不要硬寫。
